# 第 4 本延伸練習：把「預訓練資料的過濾器」當品質閘來驗收

基礎模型（TabPFN／TabICL）的預訓練資料全是合成的：一個隨機程式畫出因果圖、填入隨機函數、產出特徵與標的。
產出之後有一道**可學性過濾器**：ExtraTrees 的 out-of-bag 預測要顯著勝過「猜平均」（bootstrap p<0.05）才保留。
這道過濾器，就是你在 hvac-load-forecast P1 做的品質閘——只是閘門守的是「課本」而不是「感測器」。

執行：`python ex04_exercises.py e1`（或 e2／e3／e4／all），全部在筆電 CPU 上一分半鐘內跑完。
**先寫下你的預測，再跑，再對照 README 的結果表。** 預測錯的那一題，最值得往下追。

## E1 通過率｜原始產出有多少被丟掉？
- 做法：不過濾地抽 300 個合成資料集（2 個數值特徵、300 列），算每個的 p 值。
- 先預測：通過率大約多少？二元分類與多元分類誰比較容易通過？
- 要記錄：整體通過率、二元／多元各自的通過率、p 值直方圖（figs/ex04_e1_pvalues.png）。
- 對照：hvac P1 的 465 棟是 Pass 10／Conditional 363／Reject 92。兩道閘的「丟棄率」該用同一把尺比嗎？

## E2 探針要真的壞｜過濾器會不會放行純雜訊？
- 做法：取 60 個「已通過」的資料集。原樣重算一次 p 值（對照組），再把標籤打亂後算一次（探針）。
- 先預測：對照組通過率應該是多少？打亂後的誤放行率應該是多少？
- 要記錄：兩個比率。對照組若不是 100%，代表你重寫的統計量跟產生器內建的不一致——**先懷疑自己的程式，不要急著下結論**。
- 對照：hvac P2 的 `_inject_leak` 探針與「乾淨資料不觸發」對照斷言。

## E3 樣本數與檢定力｜同一個產生器，只改列數
- 做法：n = 50／150／300／1000，各抽 150 個資料集，比較通過率。
- 先預測：n 越大通過率會怎麼變？300→1000 還會繼續升嗎？
- 要記錄：四個通過率。**每個比率是 150 次抽樣，標準誤約 0.04**——判斷差異前先算雜訊帶。
- 對照：hvac P3 的「n<3 不判定」與 2SE 雜訊帶；PPG 專案的 MDE 反推。

## E4 類別特徵｜高基數類別欄會不會讓結構更難被看見？
- 做法：兩個特徵分別設為數值、5 類、50 類、200 類，各抽 150 個資料集。
- 先預測：類別基數越高，通過率會升還是降？差距會不會大於雜訊帶？
- 要記錄：四個通過率，並判斷哪些差距可以宣稱、哪些不行。
- 對照：nb06 在 Amazon 高基數類別資料上，CatBoost 贏過所有基礎模型。這題的結果能不能解釋那件事？（提示：不能直接解釋，想想為什麼。）

## 一句話總結
「基礎模型的能力邊界寫在它的預訓練先驗裡；先驗沒涵蓋的資料型態，就是它會輸給樹模型的地方。所以我評估基礎模型的第一步，是看我的資料像不像它的課本。」
